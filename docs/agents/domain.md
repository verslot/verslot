# Domain docs

Use a single-context layout:
- GLOSSARY.md at the repository root.
- Architecture decision records under docs/adr/.

Before exploring code, read the glossary and ADRs relevant to the task.
If they do not exist, proceed silently. Create them only when actual
domain terms or architectural decisions need to be recorded.

Use the glossary's vocabulary consistently. Explicitly flag proposals
that contradict an existing ADR.

Also consult the relevant historical design contracts indexed by
docs/README.md; they remain reference material until superseded.
