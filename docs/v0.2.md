# Verslot v0.2

## Goal

明确目标解析规则和本地状态约定，为 Node.js 安装与版本切换建立基础。

本文件是对应 [路线图 M2](roadmap.md#阶段-2目标解析与本地状态) 的设计草案，
重点回答部分版本支持和跨平台切换方式两个待决策项，不代表功能已经实现或版本已经发布。
沿用 v0.1 的命令形态；安装、卸载和查询的实现属于 M3，实际切换属于 M4。

## Commands

```text
verslot --version
verslot --help
verslot install <tool>@<version>
verslot uninstall <tool>@<version>
verslot use <tool>@<version>
verslot list
verslot current
```

`install`、`uninstall` 和 `use` 接受且仅接受一个目标，并使用相同的解析规则。
`list` 和 `current` 不接受位置参数。

v0.2 中，合法目标通过校验后仍返回 `not implemented: ...`，退出码为 `1`，
不创建目录或修改安装。非法目标在命令执行前被拒绝，错误写入 stderr，退出码为 `2`。
`list` 和 `current` 保持占位行为；帮助和版本查询保持成功退出。

## Initial provider

仅接受工具名 `node`，区分大小写。不接受 `Node`、`nodejs` 或其他工具名称。
本阶段不下载发行信息，也不判断指定版本是否真实存在。

## Target format

目标格式固定为 `node@major.minor.patch`，例如 `node@22.0.0`。

- 必须有且仅有一个 `@`，工具名和版本均不能为空。
- 版本由三个以点分隔的非负十进制整数组成，每段限定在 `u32` 范围内。
- 仅接受 ASCII 数字；除单独的 `0` 外不接受前导零。
- 不接受空白、`v` 前缀、预发布标识、构建元数据或路径分隔符。
- 不支持 `node@22`、`node@22.1`、`latest`、`lts`、通配符和版本范围。

选择完整版本号可以避免引入远程版本索引、隐式升级和不同命令的匹配差异。
后续安装和切换始终使用用户明确指定的同一版本。

错误按目标结构、工具名称、版本格式的顺序检查；首次失败即返回，不进行修正或猜测。
错误信息指出原因，并在格式错误时提供 `node@22.0.0` 作为合法示例。

## Local state

采用用户级存储，不提供项目级版本选择或自定义存储位置。

| 平台 | 存储根目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\verslot` |
| macOS / Linux | `$HOME/.verslot` |

读取对应系统环境变量仅用于定位存储目录，不提供环境变量管理功能。
根目录来源缺失、为空或不是绝对路径时返回错误，不回退到当前工作目录。

```text
<root>/
  installs/
    node/
      22.0.0/       # 完整安装的发行包内容，移除归档最外层目录
  tmp/              # 每次安装使用独立临时目录
  current/
    node            # 指向某个完整安装目录的链接
```

目录中的版本名必须来自校验后的版本数据，不能直接拼接原始目标字符串。
后续安装在同一存储根目录内完成下载、校验和解压，再提交到最终安装位置；
`tmp` 中的内容不算已安装版本。完整安装的判断和提交失败清理在 M3 实现。

当前选择以 `current/node` 链接为唯一依据，不另存一份当前版本文件。
链接缺失表示尚未选择版本；链接损坏、指向安装目录之外或版本目录不合法时，
状态读取必须报告错误，不静默选择其他版本。
除受控的当前版本链接外，安装和临时目录路径不得通过符号链接或 Windows junction
越出存储根目录；后续写入、清理和卸载必须遵守此边界。

v0.2 实现目标解析、路径构造及当前链接状态读取的内部基础，并通过临时目录测试。
生产命令暂不调用状态写入；安装目录创建与提交在 M3 接入，当前链接更新在 M4 接入。

## Version switching

为 M4 约定固定入口方案：`use` 只接受已完整安装的版本，通过更新 `current/node`
改变当前选择，不复制可执行文件，也不修改系统已有 Node.js 安装。

| 平台 | 当前版本入口 | 用户需放在 PATH 前部的目录 |
| --- | --- | --- |
| Windows | 指向安装目录的 directory junction | `%LOCALAPPDATA%\verslot\current\node` |
| macOS / Linux | 指向安装目录的符号链接 | `$HOME/.verslot/current/node/bin` |

PATH 由用户一次性配置，Verslot 不自动修改 shell 配置或系统环境变量。
此方案不新增代理可执行文件；如果其他 Node.js 路径优先，实际执行版本可能与选择不同。
后续 `current` 报告 Verslot 的选择，不能把它表述为已验证的 shell 实际执行版本。

Unix 平台采用同目录临时链接替换当前链接。Windows 的 junction 创建与替换单独实现，
不得假定其具有与 Unix 相同的原子替换能力。M4 必须验证文件占用、替换失败和恢复行为；
失败时报告错误并保留或恢复原选择，不能把部分切换报告为成功。
Windows 切换尚未经实现和验证，本草案不承诺无间隙切换或并发写入支持。

## Platforms

- Windows
- macOS
- Linux

保持单 crate、stable Rust 和禁止 unsafe Rust 的约束，隔离平台相关目录与链接操作。
本次设计不新增依赖；实现 Windows junction 如需依赖，须按项目规则说明选型理由。

## Acceptance criteria

- 三个目标命令共用解析规则，完整版本可解析，非法目标退出码为 `2`。
- 覆盖缺失或重复 `@`、未知工具、部分版本、前导零、整数溢出、空白和路径穿越输入。
- 覆盖各平台根目录构造，以及根目录来源缺失或无效的情况。
- 使用临时目录覆盖未选择版本、合法链接、损坏链接和越界链接，不修改用户真实安装。
- 合法命令仍保持占位行为，不下载、不安装、不切换；帮助与参数数量约束保持不变。
- 实现完成后按项目要求执行验证并记录结果；本文仅规定验收要求，未执行验证。

## Non-goals

- Node.js 下载、校验、解压、安装和卸载的实现
- 已安装版本列表和当前版本查询的 CLI 接入
- 实际版本切换及自动配置 PATH
- 部分版本解析、版本别名和自动升级
- 项目级版本配置及其他 provider
- 扩展系统、任务运行器、环境变量管理、dotenv、密钥管理
- shell 脚本、遥测、异步运行时、GUI
